# KrishiRent — UI-Only Flutter Prototype
Agriculture task 

A pure UI/UX click-through prototype of the KrishiRent agriculture rental
platform. **No backend, no Firebase, no real auth or payments** — everything
runs on in-memory mock data (`lib/mock_data/`) exactly as scoped in the
build prompt.

## Run it

This archive contains the `lib/`, `pubspec.yaml`, and config files only — no
platform folders (`android/`, `ios/`, `web/`, etc.), since those are
generated by the Flutter tool and don't need to be hand-written. Extract
the zip into an empty folder, then:

```bash
flutter create .          # generates android/ ios/ web/ etc. around the
                           # existing lib/ and pubspec.yaml — safe, won't
                           # touch your source files
flutter pub get
flutter run -d chrome      # or an emulator / connected device
```

## What's inside

- **State management:** `provider` + `ChangeNotifier` (`lib/providers/`) —
  intentionally simple since all data is mocked.
- **Navigation:** `go_router` (`lib/routes/app_router.dart`) — every screen
  is a real route with back-stack support.
- **Design system:** `lib/core/theme.dart` — single `AppTheme`/`AppColors`
  source of truth (Deep Agriculture Green `#1B5E20`, Leaf Green `#4CAF50`,
  Harvest Gold `#F5A623`, Warm Off-White background).
- **Mock data:** `lib/mock_data/` — 15 resources across all categories,
  bookings covering every status, categories, and demo users
  (renter / owner / admin).

## Flows you can click through

- **Auth:** Splash → Onboarding → Login (renter/owner toggle) → Register →
  fake 4-digit OTP → app shell.
- **Renter:** Home → Search/Filter → Resource Details → Select Dates →
  Booking Summary → Payment (UPI/Card/Wallet, scripted fail-then-succeed) →
  Success → My Bookings (tabbed) → Booking Details → Notifications →
  Favorites → Profile → Edit Profile.
- **Owner:** Owner Dashboard → My Resources → Add Resource (5-step form) →
  Edit Resource → Availability Calendar → Rental Requests (Approve/Reject) →
  Request Details.
- **Admin:** Admin Login → Admin Dashboard (KPI cards + `fl_chart` charts +
  pending-approval actions) → Users → Owners → Resources → Categories →
  Bookings (status tabs) → Payments → Reports → Notifications & Content →
  Settings. Drawer navigation ties it all together.

## Notes

- Login as **Owner** from the Login screen's role toggle, or jump to the
  Owner Dashboard any time from Profile → "Switch to Owner Dashboard".
- Admin Login is reachable from the Login screen or Profile screen.
- All images are emoji/icon placeholders per the no-real-photos requirement
  — swap in real assets under `assets/` and reference them in
  `pubspec.yaml` when you're ready to move past the prototype stage.
- Favorites and any newly added resources/bookings reset on hot restart —
  this is intentional (in-memory only, per the UI-only scope).
